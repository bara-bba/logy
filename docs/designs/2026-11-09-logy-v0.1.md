# logy v0.1: floating multi-repo git tree viewer

- Status: approved 2026-11-09 (feature-spec review Stages 5-8 passed); implemented in v0.1.0
- Date: 2026-11-09
- Repo / branch: logy / main (`C:\Users\lorettin\git\logy`, `git init -b main` done)
- Owner (decides): Lorenzo

## 1. Problem

Lorenzo has about 15 git repos under `C:\Users\lorettin\git`. 11 use AWS
CodeCommit remotes (`codecommit::eu-west-1://<profile>@<repo>`), the rest
GitHub. To see a repo's history or fetch/pull/push it he must open a terminal
per repo. There is no single small window that shows several repos' commit
graphs side by side with one-click sync buttons.

## 2. Goals

- A Windows desktop app named **logy** (always lower case) that lists the
  repos in a root folder and shows several repos' commit graphs at the same
  time, as side-by-side columns in one floating window.
- A **+** button on the right edge adds a repo panel; **x** removes it.
- Each panel has small **Fetch**, **Pull**, **Push** buttons.
- Clicking a commit shows its full message and changed files in the panel.
- Colours are configurable: a button accent (white by default) and the tree
  branch colours (presets, random generation, per-colour customization).
- It installs and updates with Velopack from GitHub Releases, like Lorenzo's
  app Picky.

## 3. Non-goals

- No commit, stage, checkout, branch create/delete, merge, rebase, stash,
  diff viewer or conflict resolution. Read history + fetch/pull/push only.
  When a pull cannot fast-forward, logy says so and the user resolves it in
  a terminal.
- No background running: no tray icon, no auto-start, no timer that fetches.
  Closing the window quits the process.
- No tear-off panels (each panel in its own window). Columns only in v0.1.
- No scanning of nested folders: only direct subfolders of the root.
- No force push, ever.
- No git library (LibGit2Sharp etc.); see D2.
- No history paging: a panel shows the newest 2000 commits (D13).
- No Windows Forms dependency.

| D2 | Run the user's `git.exe` as a child process | LibGit2Sharp | Uses the existing credential helpers, SSH config, hooks and `git-remote-codecommit` with no extra setup; LibGit2Sharp cannot run the `codecommit::` remote helper |
| D3 | Default root `%USERPROFILE%\git`, changeable in Settings | Several roots incl. | D4 | Pull = `git pull --ff-only` only. On divergence, show "branches diverged: rebase or merge in a terminal". No Rebase button | Rebase button; plain pull | A rebase can stop on a conflict, which logy cannot handle; never make a merge commit silently (Lorenzo agreed in design review) |
| D5 | Push never forces; first push of a branch with no upstream asks before `-u` | always `-u` | Avoid publishing a branch by accident |
| D6 | No fetch timer, no tray; close = exit | auto-fetch | No background process means no network traffic and no credential prompts while no logy window is visible; fetches happen only when asked. Lorenzo: "cannot run in background" |
| D7 | Accent default white `#FFFFFF`; used on Push, +, pin-on state, active preset button | blue | White on the dark `#202020`/`#333333` surfaces gives the highest contrast for the few accent elements and stays neutral next to the coloured tree lanes; Lorenzo chose it |
| D8 | Tree colours: 5 presets (Fluent default), Random, Custom (8 editable colours) | single fixed palette | A fixed palette cannot suit every taste or colour-vision need; 8 colours keep branches distinguishable without large tables. Lorenzo asked for presets, random and customize |
| D9 | Branch colour is stable per branch, not per column (see 6.4) | colour by lane index | Lane indexes change whenever another branch appears or ends, so a branch would change colour between refreshes; hashing the branch name gives the same colour every time. | D10 | Add `-c credential.helper=` to network commands only when EVERY remote of the repo is CodeCommit; mixed repos keep GCM and rely on the `GitErrors` noise filter | always for CodeCommit origin; filter only | Removes GCM noise without breaking auth for a GitHub remote in the same repo |

## 6. Design

### 6.1 Window

- One window, `WindowStyle=None` with a custom 34 px title bar
  (`WindowChrome`, CaptionHeight 34, ResizeBorderThickness 6), background
  `#202020`, rounded corners via DWM (`Native/DwmHelper.cs`), min size 420x300.
- Title bar, left to right: app icon 16 px, text "logy", spacer (drag area),
  then buttons: **Pin** toggle (glyph E718, sets `Topmost`), **Settings**
  (E713), **Minimize** (E921), **Maximize/Restore** (E922/E923),
  **Close** (E8BB, red hover). Double-click title toggles maximize.
- Body: a horizontal `ScrollViewer` with a `StackPanel` of panels, then a
  fixed 34 px-wide strip on the right with a 26 px accent **+** button
  (E710) at the top.
- Panel width 320 px default; a 4 px drag handle on each panel's right edge
  resizes it (min 220, max 900). Panel widths are not persisted in v0.1.
- Session fields (window Left/Top/Width/Height, `AlwaysOnTop`, `OpenRepos`
  paths in order) are saved with `SettingsStore.Update` (6.5) on close, and
  `OpenRepos` also whenever a panel is added or closed. They are restored on
  start. If the window is maximized at close, `RestoreBounds` is saved; the
  maximized state itself is not persisted. Several logy instances may run at
  once (no single-instance lock); for session fields the last one closed
  wins. A saved path that is no longer a repo is dropped silently. A saved
  position is used only if at least 100x50 DIP of the window lies inside the
  virtual screen (`SystemParameters.VirtualScreenLeft/Top/Width/Height`, in
  DIPs, which WPF window bounds also use); otherwise the window is centred
  on the primary screen.
- Closing the window while a Fetch, Pull or Push runs in any panel shows a
  `MessageBox` "<command> is running in <repo>. Quit anyway?" Yes/No. Yes
  cancels every panel's token (which kills the git process trees) and
  closes; No keeps the window open. With no command running, close exits at
  once (a running refresh is cancelled).

### 6.2 + picker

- Clicking **+** opens a `Popup` anchored left of the strip, 280x400,
  background `#2B2B2B`, containing a filter `TextBox` (focus on open,
  case-insensitive substring filter on name) and a `ListBox` of
  `RepoScanner.Scan(root)` results (sorted by folder name, case-insensitive).
  Each row: repo name, and the chip `RepoInfo.Remote.Chip` (6.7).
- Repos already open are shown disabled. Clicking a repo appends a panel at
  the right end, closes the popup, saves `OpenRepos`. Esc or click outside
  closes the popup.
- Empty result shows "No repos in <root>".

### 6.3 Repo panel

Layout, top to bottom: header (36 px), error bar (22 px, only when shown),
commit list (fills), details pane (160 px, only when a commit is selected).

Header (`#333333`):
`name` (bold 12) · chip (GH/CC/GIT, hidden when no remote) · branch name and
badges `↑N` `↓N` (hidden when 0) `●N` (changed-entry count, hidden when 0)
· spacer · **Fetch** (E895) · **Pull** (E896) · **Push** (E898, accent) ·
**Close** (E711).

Button states:
- While a Fetch, Pull or Push runs in this panel, all three are disabled and
  the clicked one shows a rotating E895 glyph (rotation off when
  `SystemParameters.ClientAreaAnimation` is false). A refresh does not
  disable them.
- Fetch/Pull/Push disabled when the repo has no remote.
- Pull disabled when there is no upstream or the upstream is gone. Push
  disabled when an upstream exists (not gone) and ahead = 0.
- Upstream gone (`RepoStatus.UpstreamGone`): the header shows a `gone` badge
  (`#8A8A8A`), Pull is disabled, Push stays enabled; Push with upstream then
  recreates the remote branch.
- After a failure the clicked button is red (`#C42B1C`) until the next
  successful command in that panel; the one-line message
  `GitErrors.Friendly(result, repo.Remote)` (6.7) appears in the error
  bar (text `#FFFFFF` on `#C42B1C`), with an x to dismiss. Clicking the bar
  text expands it to the full cleaned stderr (`GitErrors.CleanStdErr`).
- Detached HEAD: branch label "detached", Pull and Push disabled.

Commands (all via `GitRunner`, working dir = repo path, 2 min timeout,
D10 applied when `RepoInfo.AllCodeCommit` is true):
- Fetch: `git fetch --all --prune`
- Pull: `git pull --ff-only --no-rebase` (`--no-rebase` so a
  `pull.rebase=true` setting cannot turn it into a rebase). If it fails and `GitErrors.Friendly` returns
  "branches diverged", the error bar text is
  "branches diverged: rebase or merge in a terminal". When the status already
  shows ahead > 0 and behind > 0, the header also shows a `diverged` badge
  (`#C42B1C` text) and Pull stays enabled (it will report the same message).
- Push with upstream: the refresh's for-each-ref line for
  `refs/heads/<branch>` already carries `%(upstream:remotename)` and
  `%(upstream:remoteref)` (e.g. `origin` and `refs/heads/main`); strip
  `refs/heads/` to get `<name>`. No extra git call. If the remote name is `.` (the upstream is a local branch),
  Push is disabled and its tooltip says "upstream is a local branch".
  Otherwise run `git push <remote> HEAD:<name>`, so a differently named
  upstream branch is respected. Limitation: `branch.<x>.pushRemote` and
  `remote.pushDefault` are ignored; logy always pushes to the upstream's
  remote.
- Push without upstream: target remote = `origin` if it is in
  `RepoInfo.RemoteNames`, else the first name listed. A `MessageBox`
  "Publish <branch> to <remote>?" Yes/No; Yes runs
  `git push -u <remote> <branch>`.
- After every command: a full refresh (below).

Status: one call, `git status --porcelain=v2 --branch`, parsed by
`RepoStatus.Parse(text)`:
- `# branch.oid <hash>` → `HeadHash` (`(initial)` → null).
- `# branch.head <name>` → `Branch`; `(detached)` → `IsDetached = true`.
- `# branch.upstream <x>` → `Upstream` (absent → null).
- `# branch.ab +A -B` → `Ahead = A`, `Behind = B` (absent → 0, 0).
- `Upstream` present but no `branch.ab` line → `UpstreamGone = true` (the
  remote-tracking ref was deleted, e.g. by `fetch --prune`).
- Every non-empty line not starting with `#` → one changed entry;
  `Dirty` = count.

Refresh. Every refresh runs, in this order: status, then
`git for-each-ref --format=%(objectname)%1f%(refname)%1f%(upstream:remotename)%1f%(upstream:remoteref) refs/heads refs/remotes refs/tags`.
This one output gives the fingerprint, `BranchTips`, the upstream of every
local branch (used by Push and by the `.`-upstream rule) and whether
`main`/`master` exist (6.4).
The **ref fingerprint** = `Branch` + "\n" + `HeadHash` + "\n" + the full
for-each-ref output (so a checkout of another branch at the same commit, or
a changed upstream, also counts as a change).
- If the fingerprint equals the panel's previous one, only the header is
  updated: the commit list, scroll position and selected commit stay as they
  are (e.g. after a terminal `git status` or `git add`, which only touch
  `index`).
- Otherwise the graph is rebuilt: the log (6.4) with `remoteNames` =
  `RepoInfo.RemoteNames`, `BranchTips` from the same for-each-ref output, one
  `LaneLayout.Build` pass. The list keeps its vertical scroll offset; the
  selection is kept if the selected hash is still in the list, else cleared.
- Panel open and the end of Fetch/Pull/Push also run this refresh (the first
  one always rebuilds, because there is no previous fingerprint).

Commit list: a virtualized `ListBox` (one row per commit, fixed 22 px).
Rows: graph cell, short hash (7 chars, mono 10, `#8A8A8A`), ref pills,
subject (ellipsis), relative date right-aligned (`#8A8A8A`).
Graph cell width = min(8 + maxSlots x 13 px, 40% of the panel width),
maxSlots = the largest slot count over all rows of the current layout, where
a row's count is the larger of its slots before (Top) and after (Bottom) it,
so hashes stay aligned. When the cap applies, lanes past the edge are
clipped and a 1 px `#8A8A8A` vertical line at the clip edge marks the
overflow.
Tooltip on row: author, absolute date (`yyyy-MM-dd HH:mm`, local time), full hash.
If the log returned exactly 2000 commits, the last list item is a 22 px
text row "showing the newest 2000 commits" (`#8A8A8A`). It cannot be
selected and has no tooltip.

`RelativeTime.Format(unixTime, now)` (age = now - commit time):
age < 1 min → "now"; < 60 min → "{m}m"; < 24 h → "{h}h"; < 7 d → "{d}d";
< 52 weeks → "{w}w"; otherwise local date `yyyy-MM-dd`. Future times → "now".

Details pane: clicking a row selects it and opens the pane at the bottom of
the panel (160 px, `#2B2B2B`, scrollable). Content from
`git show --no-patch --format=%B <hash>` (full message, wrapped) followed by
`git diff-tree --root --no-commit-id --name-status -r -m --first-parent <hash>`
(`--root` so a root commit lists its files)
(one line per file: status letter + path, mono 10). Clicking the selected
row again, or Esc, clears the selection and hides the pane. While its git
calls run the pane shows "loading…".

Live refresh: a `FileSystemWatcher` on the git dir (including subdirs,
`InternalBufferSize` 64 KB) handling `Changed`, `Created`, `Deleted` and
`Renamed`. An event counts when its final path (for `Renamed`, the new
name), relative to the git dir, is `HEAD`, `index`, `packed-refs`,
`FETCH_HEAD`, `ORIG_HEAD`, or anything under `refs/`; names ending in
`.lock` and anything under `objects/` are ignored (git writes `x.lock`
and then renames it to `x`). The watcher's `Error` event (buffer overflow)
counts as an event. If `RepoInfo.CommonDir` is not null (worktree layout),
a second watcher with the same rules covers that dir, because refs and
packed-refs live there. Counted events are debounced 500 ms, then run the
refresh above. Watchers are disposed when the panel closes or the app exits.

Per-panel job queue: one git job runs at a time per panel (Fetch, Pull,
Push, refresh). A Fetch/Pull/Push click while a refresh runs is queued and
starts when the refresh ends (the button already shows its spinner).
Details calls (read-only) do not use the queue: they run at once, and
selecting another commit cancels the previous details calls. A refresh requested while any job is running sets
a `pending` flag instead of starting; when the running job ends, one
refresh runs if `pending` is set (several requests collapse into one).
Events that arrive while Fetch/Pull/Push runs are covered the same way,
because those commands end with a refresh anyway. Nothing is dropped. Each
panel has a `CancellationToken`; closing the panel cancels it, which kills
its running git process tree. Parsing and `LaneLayout.Build` run on a
worker thread; only the final row list is handed to the UI thread.
`GitRunner` always sets `GIT_OPTIONAL_LOCKS=0`, so logy's own `git status`
does not rewrite `.git/index`. Writes made by Pull can still fire the
watcher after Pull's own refresh; that gives one extra refresh, which finds
the same fingerprint and updates only the header, so there is no loop.

All git calls are `async` and run off the UI thread, so a slow CodeCommit
fetch in one panel does not block other panels or the window.

### 6.4 Graph model (logy.core, unit-tested)

Log command:
`git log --branches --remotes --tags HEAD --topo-order -n 2000 --format=%H%x1f%P%x1f%an%x1f%at%x1f%D%x1f%s%x1e`
(not `--all`: stash, notes and other hidden refs stay out of the graph)
Records split on `\x1e`, fields on `\x1f` (leading/trailing whitespace and
newlines of each record trimmed; empty records skipped).
`Commit(Hash, Parents[], Author, UnixTime, Refs[], Subject)` with
`Ref(Name, Kind)` and `RefKind { Head, Local, Remote, Tag }`.
`LogParser.Parse(text, remoteNames)`; `remoteNames` comes from `git remote`
(`RepoInfo.RemoteNames`, read from the repo config). `%D` is split on ", ":
- `HEAD -> main` → `Ref("HEAD", Head)` and `Ref("main", Local)`; bare `HEAD`
  (detached) → `Ref("HEAD", Head)`.
- `tag: v1` → `Ref("v1", Tag)`.
- a name starting with `<r>/` where `<r>` is in `remoteNames` → `Remote`,
  except `<r>/HEAD`, which is dropped.
- a full ref name starting with `refs/` (e.g. `refs/stash`) → dropped.
- anything else (e.g. `feature/x`) → `Local`.

Branch tips map (`BranchTips.Parse(forEachRefText, remoteNames)` →
`branchOf: hash → branch name`), from the for-each-ref output of the refresh.
Only `refs/heads/x` → `x` and `refs/remotes/<r>/x` → `x` are used
(`<r>/HEAD` and all other refs skipped). When several refs point at one
commit, a local branch wins over a remote one, then the alphabetically first
name.

Lane layout: `LaneLayout.Build(commits, mainBranch, branchOf)` → rows, one
pass, top to bottom, defined by the steps below (similar in spirit to
`git log --graph`, not a copy of it). `slots` = list of
`null` or `(expectedHash, colorKey)`. Slots never shift position; only
trailing `null` slots are trimmed. For each commit:
0. Parents are de-duplicated first (order kept, repeats dropped).
1. Slots expecting this commit: the leftmost is the commit's lane; the others
   are merge-ins (edges from those slots into this lane) and become `null`.
2. If none expects it, put it in the first `null` slot (else append), with
   colorKey = `branchOf[hash]`, else the commit hash.
3. Upgrade: if the commit's lane colorKey is a hash (not a branch name) and
   `branchOf` has this commit, the colorKey becomes that branch name from this
   row down.
4. The commit's lane now expects its first parent, keeping its colorKey.
5. Each other parent: if some slot already expects it, add an edge to that
   slot; else put it in the first `null` slot (else append) with colorKey =
   `branchOf[parent]` if present, else the parent's hash, and add an edge to it.
6. No parents: the lane becomes `null`.
7. Trailing `null` slots are trimmed.

A merged branch whose tip is reached through a merge's second parent is
therefore coloured by its name (step 5 with `branchOf`), the same as before
the merge. Parents that are not among the 2000 loaded commits leave
their lane running to the bottom of the list.

Row record (everything is known while processing that row; no row is
changed afterwards). A row is drawn in two halves around its centre:
- `CommitSlot`, `CommitColorKey`.
- `Top` segments (row top → centre), from the slots as they were BEFORE this
  row: each non-null slot i that expects this commit → `(i → CommitSlot,
  colorKey of slot i)`; each other non-null slot i → `(i → i, its colorKey)`.
- `Bottom` segments (centre → row bottom), from the slots AFTER this row:
  the commit's own lane `(CommitSlot → CommitSlot, CommitColorKey)` if it
  still exists (`CommitColorKey` is the value after the step 3 upgrade, and
  is also the dot colour); each slot j that this commit linked in step 5 (new
  or existing) `(CommitSlot → j, colorKey of slot j)`; each other non-null
  slot i `(i → i, its colorKey)`.
So a merge-in is drawn in the top half of the commit it merges into, and a
fork is drawn in the bottom half of the commit that forks.

`mainBranch`: the first of `main`, `master` that has a `refs/heads/<name>` line
in the refresh's for-each-ref output, else the current branch,
else (detached, no main/master) the string `HEAD`, which matches no colorKey.

Colour: `LaneLayout.ColorIndex(colorKey, mainBranch, paletteCount)`:
paletteCount < 2 → 0; colorKey == mainBranch → 0; else
`FNV-1a-32(UTF-8 bytes of colorKey) % (paletteCount - 1) + 1`. So the same
branch name always gets the same colour across sessions for the same palette
size (a custom palette with a different number of valid colours changes the
modulus), and main is always
colour 0. Edges and dots use the lane's colour. A branch pill's colour is
`ColorIndex` of its branch name: the Local name, or for a Remote ref the name
with its `<r>/` prefix removed (so `origin/main` and `main` share a colour,
matching the lane). Pill text colour is `Palettes.Ink` of the pill colour. Tags use pill `#4A4A4A`, white text.
`Ref(HEAD)` gets no pill; the HEAD commit is shown only by its ringed dot.
Pill order: local branches, remote branches, tags (each in `%D` order).

Drawing (WPF): each row's graph cell is a custom `FrameworkElement`
(`GraphCell`) that draws with `DrawingContext`: 2.2 px lines; a straight
vertical line for `i → i`; a cubic Bezier for `i → j` (i ≠ j); a 4.5 px
radius filled dot for the commit (HEAD commit: filled dot with a 1.5 px
`#202020` inner ring). Lane x = 8 + slot x 13, row centre y = 11.

### 6.5 Settings

`SettingsStore` (logy.core, wraps `JsonStore`):
- `Load()` → `LogySettings` (missing or corrupt file → defaults).
- `Update(Action<LogySettings> change)`: load the file again, apply `change`,
  save atomically, return the saved object. The save writes a temp file with
  a per-process name (`settings.json.<pid>.tmp`), then moves it over
  `settings.json`, retrying the move up to 3 times 50 ms apart on
  `IOException`. Callers pass only the fields
  they own: MainWindow the session fields (6.1), the Settings window the
  appearance fields (`RootFolder`, `Accent`, `TreePreset`, `CustomColors`).
  The app also applies the same change to its in-memory `App.Settings`.

Settings window: modal, 420x520, same dark style, no border. Sections:
- **Root folder**: path text + **Browse** (`Microsoft.Win32.OpenFolderDialog`,
  .NET 8 WPF). Changing it does not close open panels.
- **Accent**: 6 solid swatches (`Palettes.Accents`, white first) + hex box.
  The hex box applies and saves on every text change where

### 6.7 Contracts of the existing core code

This section specifies the core code that already exists in the scaffold,
including the additions listed for it in section 7.

`GitRunner.RunAsync(repoPath, args, skipCredentialStore, timeout, ct)`:
- Starts `git` with `ProcessStartInfo.ArgumentList` (no shell, so repo
  names, branch names and paths need no quoting), `CreateNoWindow`.
- Arguments: `-C <repoPath> -c color.ui=never -c core.quotepath=off`, then
  `-c credential.helper=` when `skipCredentialStore` (D10), then `args`.
- Environment: `GIT_TERMINAL_PROMPT=0` and `GIT_OPTIONAL_LOCKS=0`. No SSH
  setting: none of the current remotes use SSH (all are `codecommit::` or
  HTTPS GitHub); an SSH prompt on a future remote is bounded by the
  2-minute timeout and the process-tree kill. Git Credential Manager may still show its own login window for GitHub;
  that is allowed, because it is the only way to sign in again.
- stdin is redirected and closed at once, so a hook that reads stdin gets
  end-of-file instead of hanging.
- stdout and stderr are read as UTF-8 (with `core.quotepath=off`, non-ASCII
  subjects and paths such as `perché` arrive as text, not octal escapes).
- On timeout (default 2 min) or cancellation it kills the whole process tree
  (`Kill(entireProcessTree: true)`), which also ends `git-remote-codecommit`
  child processes. Timeout returns `TimedOut = true`; cancellation throws
  `OperationCanceledException`.

`RepoInfo(Name, Path, GitDir, Remote)` plus the new `RemoteNames`,
`CommonDir` and `AllCodeCommit` (section 7). `Name` = folder name, `Path` = full path, `GitDir` =
`.git` folder or the target of the `gitdir:` pointer file, `Remote` =
`RemoteInfo.Parse(origin URL, else the first remote's URL)`.

`RemoteInfo.Parse(url)`: empty → `None`; starts with `codecommit:` or
contains `git-codecommit.` → `CodeCommit` (profile = text between `//` and
`@` of a `codecommit:` URL, else null); contains `github.com` → `GitHub`;
anything else → `Other`. `Chip`: GitHub "GH", CodeCommit "CC", Other "GIT",
None "" (no chip shown).

`GitErrors.CleanStdErr(stderr)` drops lines containing
"Failed to write item to store" or "The array bounds are invalid".
`GitErrors.Friendly(result, remote)` checks the cleaned stderr
(case-insensitive) in this order and returns the first match:

| Condition | Message |
|---|---|
| timed out | `timed out` |
| CodeCommit remote and stderr has `ExpiredToken`, `token has expired`, `expired token`, `Unable to locate credentials`, `Unable to load credentials`, or both `could not be found` and `profile` | `<profile or "AWS">: credentials expired or missing` |
| `Could not resolve host`, or `unable to access` + `resolve` | `offline: cannot reach remote` |
| `Not possible to fast-forward`, `have diverged`, `divergent branches` | `branches diverged` (Pull shows it as "branches diverged: rebase or merge in a terminal") |
| `[rejected]`, `non-fast-forward`, `fetch first` | `push rejected: pull first` |
| `has no upstream branch`, `no tracking information` | `no upstream branch` |
| `Authentication failed`, `returned error: 403`, `Permission denied` | `authentication failed` |
| `would be overwritten`, `Please commit your changes or stash them` | `local changes block this; commit or stash first` |
| otherwise | last non-empty stderr line without a leading `fatal: `/`error: `/`hint: `; empty → `git exited with code N` |

`Palettes.IsValid(hex)`: true for exactly 6 hex digits with an optional
leading `#`. `Palettes.Ink(hex)`: luma = 0.299 R + 0.587 G + 0.114 B (0-255);
luma > 150 → `#202020`, else `#FFFFFF`; invalid input → `#FFFFFF`.

## 9. Risks and rollback

- Push and pull change real repos. Fetch and an ff-only pull can be undone
  locally (`ORIG_HEAD`, reflog). Push publishes commits to everyone with
  access to the remote and cannot be taken back locally; the guards are no
  force push and the D5 confirmation, which covers only the first push of a
  branch.
- Security:
  - logy runs git exactly as a terminal would, so repo hooks (e.g.
    `post-merge` on Pull) and repo-local config (e.g. `core.fsmonitor`,
    `core.sshCommand`) run. They also run on the automatic `git status` of
    every refresh. This is accepted because the root folder holds the
    user's own repos.
  - Repo, branch and remote names come from the repo. They reach git only
    through `ProcessStartInfo.ArgumentList` (no shell) and the UI only as
    plain WPF text and `MessageBox` text (no markup), so they cannot inject
    commands.
  - D10's `-c credential.helper=` stops git from reading or storing
    credentials through GCM for that one command. CodeCommit authentication
    comes from `git-remote-codecommit` and the AWS profile, which do not use
    the credential helper.
- `FileSystemWatcher` can report many events during a fetch or gc. There is
  at most one refresh per 500 ms quiet period, and the graph is rebuilt only
  when the branch, HEAD or refs change.
- Repos with more than 2000 commits show only the newest 2000 (D13).
- CodeCommit credential errors vary by helper version; unknown messages fall
  back to the last stderr line.
- `git` missing from PATH: at startup logy runs `git --version` once; if it
  fails, one dialog "git not found on PATH" is shown, the window opens, and
  the + picker shows repos but panels show that message instead of a graph.
- Rollback: logy writes `%APPDATA%\logy\settings.json`; Velopack installs
  into and updates `%LOCALAPPDATA%\logy`. Uninstall via Windows "Installed
  apps" (Velopack) and delete `%APPDATA%\logy`.

## 12. v0.3.0: create, approve and merge pull requests (2026-11-12)

Replaces the v0.2 "read-only" rule. Every write is a click plus a Yes/No confirmation; nothing
runs on its own. One pull request write at a time per panel; failures go to the error bar.

- **PR view bar:** accent **New pull request** button and a status line ("created #5").
- **New pull request** (`CreatePullWindow`): FROM = local branches (default: current branch),
  INTO = branches on the PR remote (`origin`, else the first remote; default `main`, else
  `master`, else the first), title (default: the source tip's subject), optional description.
  If the source branch is missing on the remote or its tip differs, logy asks
  "Push it first?" and runs `git push -u <remote> <b>` (no upstream) or
  `git push <remote> <b>:<b>`, through the normal Push button and job queue. Then it creates
  the pull request (GitHub `POST /pulls`; CodeCommit `CreatePullRequest`) and selects it.
- **Selecting a pull request** shows a 170 px pane: `#id title`, author and branches,
  description, and buttons **Approve**, one **Merge** button per method, **Open** (browser).
  - Merge methods: GitHub merge commit (default), squash, rebase; CodeCommit fast-forward
    (default), squash, merge commit (three-way). GitHub passes the head `sha`, CodeCommit the
    fresh source commit id, so a branch that moved since the list was read is refused.
  - After a merge: the list reloads and the panel runs Fetch so the merge shows in the tree.
  - Approve: GitHub review `event=APPROVE`; CodeCommit `UpdatePullRequestApprovalState` with
    the freshly read revision id. Both hosts refuse approval by the pull request's author;
    logy shows "you can't approve your own pull request".
- **Credentials:** GitHub writes need the token Git Credential Manager stores; without it:
  "no GitHub login stored: push once from a terminal to sign in". On 2026-11-12 IAM
  simulation allowed CreatePullRequest, UpdatePullRequestApprovalState and all three
  MergePullRequestBy* actions for both `admin-barbara` and `admin-ae`
  (role `IibsAdminAccess-DO-NOT-DELETE`). Both profiles resolve to the same identity, so
  CodeCommit treats a PR created with either as yours.
- No comments, no closing/declining, no branch deletion after merge, no approval rules.
